## Using a folder

Open Radio's music-source menu and choose **Choose music folder…**. Select a
music folder or album in Finder/Files. The app copies playable songs, including
subfolders, into its private `Application Support/PulseCanvas/PersonalRadio`
collection and starts Radio. **My music folder** reopens that collection later.
The source menu also offers **Shuffle songs**; turning it off follows filename
order, including the subfolder path. The queue repeats continuously. Next song,
pause/resume, seeking, music-driven visuals and the existing mobile background
playback transport are reused.

The import accepts up to 500 candidate audio files. Each playable file must be
at most 100 MB and two hours long. Supported extensions are MP3, M4A, AAC, WAV,
AIF/AIFF, CAF, FLAC, MP4 with audio, and ALAC. System codec support still applies.
Hidden files, packages and symbolic links are excluded. Files with an accepted
extension but invalid audio, excessive size/duration, or read errors are skipped;
a partial import reports its skipped count. Empty/failed/cancelled imports clean
partial copies and preserve the previous playlist. Successful replacements clean
the old owned copy; the original selected folder is never changed. Folders from
cloud providers should be downloaded before import. The collection is a snapshot,
not a live filesystem watcher; choose the folder again to refresh it.

The app does not decode the whole album into RAM. Mac/mobile prepare the current
and next song; Vision prepares one song at a time. Radio skips unreadable tracks
and stops safely if none can play. Imported copies remain available after the
original folder moves or disappears. The collection and selected source persist
across launches; opening Radio does not automatically start playback.

## Separation from Studio

Personal folder music is Radio-only. It does not enter Studio's **Choose music**
list or catalog song favorites. Source selection never overwrites the saved
server/library source used by Studio. Selecting All music, a server station, or
Favorite songs returns to catalog Radio. Catalog song hearts remain unchanged;
personal collection songs have no catalog-favorite heart.

On mobile, Save project and Export MP4 are unavailable while personal Radio is
active, so its transient soundtrack cannot become a Studio project/export.
Leaving Radio restores the previous Studio soundtrack and settings. Importing a
single user audio file directly into Studio remains supported. Studio's catalog
picker, favorites filter, single-track timeline and MP4 export remain available
on Mac, iPhone/iPad and Vision Pro.

## Verification — October 20, 2026

- Shared Radio smoke suite passed: nested album import, malformed-audio skipping,
  imported-copy integrity after deleting the original folder, ordered queue wrap,
  actual audio completion advancing to the next track, persisted playlist reopen,
  empty-import rollback/cleanup, owned-copy cleanup with external-path rejection, catalog-favorites isolation, Studio source and
  soundtrack restoration, and switching back to catalog Radio. Existing queue,
  favorites, catalog, transport, prefetch and bounded-failure tests also passed.
- Native iPhone 17 and iPad mini simulator UI tests passed, with normal command
  exit 0. The real async importer receives an isolated fixture album at launch;
  the tests verify playback, one-song Next looping, the absent catalog-song heart,
  disabled Radio MP4 export, catalog-only Studio music browsing, and returning to
  All music. The operating system folder-picker selection itself is not automated.
- Vision transport tests passed for persisted personal collection playback,
  automatic one-song looping, independent Studio catalog source, and returning to
  server music, alongside existing Studio/Radio transport and project checks.
- Debug Mac, iOS simulator and visionOS simulator builds passed. A tvOS simulator
  compatibility build checks the shared RadioLibrary code; this does not add a
  folder-picker UI to Apple TV.
- Physical-device folder providers, large real-world albums, and manual Mac/Vision
  folder-picker UI were not tested. New code uses the existing sandbox lease and
  playback transports; no claim of physical-device validation is made.

An initial Vision compilation failed on initialization order and was corrected.
An initial new Vision fixture used an MP3 file with an M4A extension and failed
import; the fixture now preserves its MP3 extension and the test passes. These
failures are retained in the local evidence, not counted as successful checks.
